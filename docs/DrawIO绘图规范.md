# DrawIO 绘图规范

> **适用**：画 / 改任何 drawio 图都按这份来。仓库根目录的 `AGENTS.md` 让代码助手一进仓库就读它；
> 想在任何路径都生效，按 README 把一行指向这份文件的话加进助手的全局说明（Codex：`~/.codex/AGENTS.md`）。
> - **画新图**：第一节流程 + 第二节深色演示风格，用户不用再发提示词
> - **改已有的图**：第六节；第八节是一张旧浅色练习图的专用规则（那张图不在本仓库，新图不用）
> - 通用：第三节走线、第四节符号、第五节自查、第七节踩坑
>
> 工具在仓库的 `tools/`：
> - `drawio_kit.py`：深色风格的生成库，配色、字号、版式部件都在里面，用法写在文件头
> - `drawio_check.py`、`drawio_deep_check.py`：两个自查脚本
> - `new_diagram.py`：新建一张图的工作文件夹（复制上面三个文件 + 能直接跑的生成脚本模板）
>
> 样板：`examples/mp_pipeline/`（4 页成图 + 生成脚本 + 三份中间文档）；风格参考：`docs/ref/`（同学的 SuperO3 原图）

## 一、画新图的流程

用户 2026-10-09 写的四步提示词原文在 `DrawIO画图提示词.md`（本目录），照它做：
text.md（文字描述）→ ascii.md（ASCII 图）→ design.md（合并 + 图例约定）→ .drawio + 每页 PNG。

**执行方式**（2026-10-09 用户定，覆盖提示词里的「暂停等我回复继续」）：
- 一口气跑到出图：每步做完对照源码自检，有错当场改，不逐步停下来问
- 只问真正必要的问题，比如没说画哪份代码、输出文件夹已经存在
- 最后汇报：每步做了什么、自检结果、自己改正过的错、替用户定的默认值、
  图和文字的一致性清单（图里有而文字没有的、被省略的重要内容）、输出文件列表

**「本次任务」用户没给的项，用这些默认值**：

| 项 | 默认 |
| --- | --- |
| 输出文件夹 | 当前工作目录下 `diagrams/<英文小写下划线名>/`；已存在就先问 |
| 源码 / 文档路径 | 用户没说就问 |
| 文字描述行数上限 | 150 |
| 图中文字语言 | 中英结合：模块名、信号名、术语用英文，短注释用中文（覆盖提示词模板里的 English） |
| 作者署名 | `by Pinxu Wang` |
| 样板图 | `examples/mp_pipeline/` 的成图；风格参考 `docs/ref/` |
| 强调点、视图 | 自己按设计定，汇报里说明；总览页必须单独讲得清 |

## 二、深色演示风格（新图默认）

1. **版式**（一页 1920 × 1080）：
   - 顶部：标题 + 署名（26px），下面一行关键参数（13px）
   - 左栏（x 24–254）：配置表、图例、页面导航（VIEWS IN THIS FILE，可点跳页）
   - 中间：主图；虚线框是模块边界，框角写模块名；子部件放进带标题的容器
   - 右栏（x 1656–1896）：KEY DESIGN DECISIONS，编号跟图上的编号圆一一对应
2. **文字少**：块里只放名字，最多再加 1 行短注释；决策每条最多 2 行；字号不小于 10px；文字全部横排
3. **配色**：按功能分，全图同一含义；色值在 kit 的 `CAT`（块）和 `LINE`（线），写进该图 design.md 的「图例约定」

   | 块 | 用在 | 线 | 用在 |
   | --- | --- | --- | --- |
   | 紫 storage | 寄存器、存储、缓冲 | 紫粗实线 data | 数据 |
   | 蓝 datapath | 运算、mux | 蓝细实线 addr | 地址、PC |
   | 琥珀 control | 译码、停顿、仲裁 | 琥珀细实线 ctrl | 控制、握手 |
   | 红 recovery | 冲刷、作废、重试 | 青实线 fwd | 前递、旁路 |
   | 绿 commit | 写回、提交 | 红虚线 flush | 冲刷、bubble |
   | 灰 external | 设计外部的单元 | 绿实线 commit | 写回、提交 |

   - 深色背景 `#14161b`；每页 `mxGraphModel` 加 `adaptiveColors="none"`，否则 draw.io 深色模式会把深色填充反转成浅色
   - 字体：正文 Helvetica；信号名、模块名、代码用 Menlo
4. **生成方式**：用脚本，不手工拖
   - `python3 tools/new_diagram.py <输出文件夹>` 起步：复制 kit 和两个自查脚本，放一个能直接跑的 `gen_drawio.py`；
     再按设计写 `pages_*.py`；每个文件不超过 400 行
   - 所有单元 `parent="1"`、绝对坐标（自查脚本不认嵌套坐标）
   - 连线用带绝对端点的自由线（`sourcePoint` / `targetPoint` + 拐点），不靠形状的连接点，梯形转向后也不会接错边
   - `python3 gen_drawio.py --export --check`：写 .drawio、导出每页 2 倍 PNG、每页跑两个自查脚本
5. **多页**：总览 + 细节页（数据通路、时序、存储结构等），总览页单独能讲清；导出用 `--page-index N`（从 1 开始）
6. **长距离信号用同名标签接**：跨大半张图、要穿好几根线的信号，两头各画一小段，标同一个名字（例：flush、br_target）；
   两头的名字一字不差
7. **简化的边界**：省细节只能删「不改变谁喂谁」的块；旁路缓冲（hold）画在主路旁边，别串在主路上；
   画流水寄存器前先对一遍代码里的结构体字段

## 三、走线（通用）

1. **只走水平、竖直段**，禁止斜线（旧图用 `edgeStyle=orthogonalEdgeStyle`；新图的自由线相邻两点必须同 x 或同 y）
2. **线不穿模块框**：容器框内部的连线、从外面进容器接里面的块不算
3. **走线要短**：信号从离目标最近的地方取，别从远处绕（例：WB→EX 直接从 mux 正下方的写回线往上拉）
4. **扇出**：一条干线 + 分叉点小圆，不画成几条独立的线（旧图分叉点用黑色，新图用线的颜色）
5. **取信号的线起点加小圆点**：旧图用 `startArrow=oval;startFill=1`，新图在分叉处放 kit 的 `dot`
6. **线不压字**，包括线上的标签
7. **出点、入点对齐同一高度**：差 1px 也会折一下
8. **很短的线段把箭头调小**：`endSize=4`，不然箭头挤在拐角
9. **尽量不交叉**：补充自查脚本会数交叉，能绕开就绕开

## 四、符号（通用）

1. **mux 画梯形**：数据从宽边进、结果从窄边出；sel 在旁边用 `sel = …` 标注，别从斜边进数据（看起来像 sel）
   - 新图（kit 的 `trap`）：`direction` 取 east = 宽边在下，west = 宽边在上，south = 宽边在左，north = 宽边在右
   - 旧图：一律竖梯形 `shape=trapezoid;perimeter=trapezoidPerimeter;direction=south;fixedSize=1;size=N`（左进右出）
2. **`direction=south` 会把连接点一起转掉**（只有用形状连接点的旧图有这个问题），style 里的 `entryX/entryY`（出线同理 `exitX/exitY`）要换算：

   | 图上看到的位置 | style 里写 |
   | --- | --- |
   | 左边第 t 处 | `(t, 1)` |
   | 右边第 t 处 | `(t, 0)` |
   | 底边第 s 处 | `(1, 1-s)` |
   | 顶边第 s 处 | `(0, 1-s)` |

3. **框要容得下字**：竖梯形斜的是上下两条边，宽度不减、高度减 2×size；放不下就加宽框或把字号调小

## 五、自查（通用，必须做，不能只看脚本数字）

1. **两个脚本都跑**（新图的 `gen_drawio.py --check` 已经包含）：
   ```bash
   drawio --export --format svg -o x.svg 图.drawio      # draw.io 命令行，各系统的路径见 README
   python3 tools/drawio_check.py 图.drawio x.svg --containers id1,id2
   python3 tools/drawio_deep_check.py 图.drawio --containers id1,id2
   ```
   - `drawio_check.py`：前 5 项必须是 0（斜线、线穿模块框、线压文字框、框重叠、悬空引用）；
     后 3 项按字宽估算（线上标签压线 / 框 / 字、标签互相重叠、字放不下），报出来的逐个放大看图判断
   - `drawio_deep_check.py`：字压字、字压框、线穿编号圆、箭头悬空、线交叉 / 重叠、中英之间空格，都应为 0
   - 多页文件要每页单独成文件再查（kit 的 `check` 就是这样做的），不然会把别页的字算进来
2. **脚本报 0 不等于没问题**：导出 2 倍 PNG（`--format png --scale 2`），逐区放大看，至少两轮；重点看改过的地方和它周围
3. **对内容**：把图上所有文字导出来逐条对照源码：名字、连接、数值；旧标签、进度框、标题有没有过期
4. **改一处，查它的邻居**：标签改长了，看周围的线；颜色改了，看配套的字色和图例
5. **配色语义**：每条线、每个块的颜色符合图例含义（例：PC 值走蓝线，不走紫线）

## 六、改已有的图（通用）

1. **先请用户关掉 draw.io**：他常开着图边看边改代码，两边同时写会冲突。macOS / Linux 用 `pgrep -fl draw.io` 确认进程没了再动
2. **重新读一遍文件**：用户经常自己改（挪位置、加字、重画线），一切以文件现状为准
3. **先备份原文件**：改坏了能对比、能回退
4. **只做增量修改**：用 python 字符串替换指定的 `mxCell`，不整份重写
   - 不认识的单元（用户加的）不碰、不重排
   - 用户的标注或连线已经过期、画错（跟当前代码不符），可以改，改完在回复里说清改了哪、为什么
   - 真要大改布局：先问用户
   - 脚本生成的新图：改生成脚本再重新生成，不手改 .drawio

## 七、踩过的坑

| 问题 | 原因 | 现在怎么防 |
| --- | --- | --- |
| 线接到了梯形的斜边上 | `direction=south` 把连接点一起转了 | 第四节换算表；新图用绝对端点的自由线 |
| 脚本报 0，图上却有问题 | 旧脚本只认矩形，不查线上标签和字放不放得下 | 脚本升到 8 项 + 补充脚本 + 第五节第 2 条 |
| 「pc_next」超出 mux 框 | 缩小看图，看不出几像素的溢出 | 2 倍放大逐区看 |
| dmem 标签、进度框过期 | 只检查新加的，没回头核对旧的 | 第五节第 3 条 |
| 标签改长后压到旁边的线 | 改一处没看邻居 | 第五节第 4 条 |
| 说明单独画成面板、字太多 | 没照 ppt 的画法 | 旧图：第八节第 1 条；新图：第二节第 2 条 |
| 颜色按「哪一片加的」来分 | 按开发顺序分色，读图时没用 | 第二节第 3 条：按功能分色 |
| 把整个图例删了 | 误读用户的话：要删的是「按片分色」那套逻辑，不是图例本身 | 图例保留，只解释功能配色 |
| 保持寄存器串在主数据通路上（rdata → hold → load_val） | 读起来像每次 load 都多一级 | 第二节第 7 条（2026-10-09） |
| 总览省掉 a/b mux，前递 mux 直连 ALU | 简化删掉了会改变数据来源的块，像是 ALU 吃不到 imm / pc | 第二节第 7 条 |
| inst 画进 id_reg | 没对 types.sv：id_reg 根本没有指令字段 | 第二节第 7 条 |
| draw.io 深色模式下深色块变成浅色 | 自适应配色默认开着 | 第二节第 3 条：`adaptiveColors="none"` |
| 多页文件自查报了一堆别页的字 | 检查脚本按整个文件取文字 | 第五节第 1 条：每页单独查 |
| pc_wdata 一路紫蓝混用 | PC 值走了数据线的颜色 | 第五节第 5 条 |

## 八、浅色练习图专用（只用于 `UIUC/411/mp_pipeline_架构图.drawio`，那张图不在本仓库）

这张图跟着 CP3 练习进度画，2026-09-13 ~ 09-28 定的规则，改它时照这节，不套第二节的深色风格。

1. **照课程 ppt 的画法**：新机制直接画进主图，**不另开说明面板**；少写字，能用符号和连线表达的不写成句子
2. **术语用英文**：Forwarding、flush、bubble……不写中文「转发」
3. **颜色**（按功能上色，配图例）：

   | 功能 | 填充 / 边框 |
   | --- | --- |
   | 模块、regfile | `#f5f5f5` / `#666666` |
   | 流水寄存器、hold 寄存器 | `#e1d5e7` / `#9673a6` |
   | mux | `#dae8fc` / `#6c8ebf` |
   | 运算：ALU、CMP、加法器、扩展、移位 | `#d5e8d4` / `#82b366` |
   | 冒险控制：load-use、`&` 门 | `#f8cecc` / `#b85450` |
   | 设计外部：imem、dmem、RVFI | `#ffe6cc` / `#d79b00` |
   | 说明面板里的信号值 | `#ffffff` / `#666666` |

   - 控制线（pipe_en、stall、bubble、flush）用红色 `#b85450`
   - sel 标签的字色跟所属的块：mux 用深蓝 `#1a5fb4`，运算用深绿 `#2e7d32`
   - **不按「哪一片加的」上色**
   - **图里要有「颜色 = 功能」图例**：列出每种方块颜色和线颜色各代表什么，放在 RVFI 正下方；mux 的色块直接画成竖梯形
4. **每做完一片**：新加的块按上表配色；进度框里划掉做完的，标题里的进度数字改掉
